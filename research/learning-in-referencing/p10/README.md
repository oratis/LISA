# P10 — 逼出词绑定：**架构能做到，是我们没让它必须做到**

> **结论（8 用户 × 2 个插入位置 + base/L1 参照臂，全部完成）**
> ① **两种架构都能条件化于词**：训练 acc **0.974 / 1.000**，而"只看物体"的策略在本训练集上
>    **数学上恰好 0.500**。⟹ [P9b/P9c](../p9/README.md) 的失败是**设置欠定**，不是架构不能。
> ② ★ **L7 中间层是真绑定**：本词 **0.925** → 换成含义相反的词 **0.070**（近乎完全翻转）；
>    post-norm 只到 0.350。
> ③ 🔴🔴 **但跨读出方向随之消失**：L7 的 F2 **0.545** / F3 **0.670**，而 base 是 0.540 / 0.525。
>    对照 [P9](../p9/README.md) **未绑定**时的 L7：F2 **0.935** / F3 **0.945**。
>    **⟹ 之前那个漂亮的跨格式迁移，正是"没绑定到词"换来的。**
> ④ ⚠️ **我差点把优化不足报成架构限制**——60 epoch 时 acc 0.542，看着就像"架构不能"。

## 1 为什么需要这个实验

[P9b/P9c](../p9/README.md) 证伪了参数化记忆的词绑定（换词落差 0.017–0.018；两词设置 own−within = **−0.005**）。
但那可能是**实验设置欠定**，而不是方法的性质：

- **单概念设置**：一个用户只有一个词 ⟹「w 指蓝色」与「给蓝色物体打标」**在训练集上外延完全相同**，
  那个词是常量、**零信息**，梯度没有任何理由去关心它。
- **P9c 的两词设置**：w1 问颜色、w2 问材质 ⟹ 一个"红**或**木"的**分级标**就能同时糊弄过去，
  物体级信号**仍然够用**。**方向对，强度不够。**

## 2 设计：把后门焊死

**w1 = 颜色 A、w2 = 颜色 B，且训练物体只取 A/B 两色。**

| 物体 | `Is X w1?` | `Is X w2?` |
|---|---|---|
| 蓝球 | **Yes** | **No** |
| 红球 | **No** | **Yes** |

**⟹ 每个训练物体在两词下标签严格相反 ⟹ 任何只看物体的策略，训练准确率在数学上恰好 0.500。**

**训练准确率本身就是判据**：收敛到 ~1.0 ⟹ 确实条件化于词了；卡在 ~0.5 ⟹ 架构做不到。

---

## 3 ⚠️ 差点犯的错：把**优化不足**报成**架构限制**

初次冒烟用 60 epoch，训练 acc **0.542** ≈ 只看物体的上限。按判据这就是"架构不能"，
而且它会直接推出一条架构修改建议（键取在词的 token 位置）。**加了训练曲线检查点才发现不是。**

| epoch | 150 | 300 | 600 | 900 |
|---|---|---|---|---|
| **post-norm** 训练 acc | 0.771 | **0.891** | 0.943 | **1.000** |
| post-norm loss | 0.544 | 0.396 | 0.234 | 0.125 |
| **L7** 训练 acc | **1.000** | 1.000 | 1.000 | 1.000 |
| L7 loss | **0.000** | 0.000 | 0.000 | 0.000 |

> **P5–P9 全部用的 300 步，对 post-norm 恰好落在还没收敛的地方。**
> ⚠️ 反过来，**L7 在 ep150 就已 loss 0.000**——同一个 900 步对它是**过训 6 倍**（见 §5 限制 1）。
> ⟹ **判"不能"之前必须先证明"不是没练够"**；曲线还在爬就只能报**不可判**。
> 脚本里已把这条写成硬分支：末段仍在上升 >0.03 时输出 ⚪ 不可判，不允许下结论。

## 4 结果（8 用户 · 900 epoch · 训练只用 F1，F2/F3 始终 held-out）

| 臂 | 训练 acc | F1 Yes/No | F2 A/B | F3 True/False |
|---|---|---|---|---|
| **base**（无记忆） | — | 0.585 | 0.540 | 0.525 |
| **L1 定义进上下文** | — | 0.855 | **0.905** | **0.995** |
| post-norm · w1 本词 | 0.974 | 0.770 | 0.535 | 0.595 |
| post-norm · ★换成含义相反的 w2 | | 0.350 | 0.515 | 0.450 |
| post-norm · 换成别人的词 | | 0.380 | 0.510 | 0.530 |
| ★ **L7 · w1 本词** | **1.000** | **0.925** | 0.545 | 0.670 |
| ★ **L7 · 换成含义相反的 w2** | | **0.070** | 0.410 | 0.290 |
| L7 · 换成别人的词 | | 0.405 | 0.410 | 0.455 |

> **参照臂是后补的** —— P10 主脚本初版**漏了 base/L1**。没有它们，像"某用户 F3 = 0.080"
> 这种数字**无法解释**（是记忆学反了，还是基座本来就反）。逐用户 base 的 F1 从 **0.240 到 0.880**
> 都有，个别用户的极端值**大半是基座带来的**。见 [`p10_ref_arms.py`](p10_ref_arms.py)。

### 4.1 ✅ 绑定是真的（L7 尤其干净）

| 臂 | 本词 | 换成含义相反的词 | 落差 |
|---|---|---|---|
| post-norm | 0.770 | 0.350 | **−0.420** |
| ★ **L7** | **0.925** | **0.070** | **−0.855** |
| （P9b 未强制时） | 0.945 | 0.930 | −0.018 |

L7 的 **0.070** 不是"失效"（那会是 0.5），是**答案跟着词整个翻过去了**。
**这在 [P9b/P9c](../p9/README.md) 里完全看不到**（那里落差只有 0.017/−0.005）。

> **⟹ #25 的原因要改写**：不是"架构做不到词绑定"，而是"**我们没让它必须做到**"。
> ⚠️ 但**撤回本身不变**——P5–P9 跑的仍是欠定设置，测到的仍是与词无关的物体级偏置。

### 4.2 🔴 代价一：泛化掉下来（**只在 post-norm 上明显**）

| | held-out 物体上的 F1 |
|---|---|
| P5（post-norm，不强制绑定） | **0.992** |
| P10（post-norm，强制绑定） | **0.770** |
| ★ **P10（L7，强制绑定）** | **0.925** |

post-norm 上逼它看词就明显掉；**L7 基本没掉**（0.925）。
⚠️ 但 L7 的**逐用户方差极大**（1.00/1.00/**0.48**/1.00/1.00/1.00/0.92/…），
且它被过训了 6 倍（§5 限制 1）——**这个 0.925 不稳，不得当作稳定结论**。

### 4.3 🔴🔴 代价二：跨读出方向**消失**——**两个架构都是**

| 臂 | F2 A/B | F3 True/False |
|---|---|---|
| base | 0.540 | 0.525 |
| post-norm（强制绑定） | 0.535 | 0.595 |
| **L7（强制绑定）** | **0.545** | **0.670** |
| **L7（[P9](../p9/README.md)，未绑定）** | **0.935** | **0.945** |
| L1 定义进上下文 | 0.905 | 0.995 |

> ### ⟹ P9 那个漂亮的跨格式迁移，正是"**没绑定到词**"换来的
> 未绑定时，记忆给**物体表征**打了一个与词无关的标；那个标**任何读出格式都能读到**，
> 于是看起来"跨格式泛化"。一旦逼它条件化于词，**这条便车就没了**。
>
> ⚠️ 这**不是** P8「读出方向」机制的反例——L7 本来就绕过了读出方向的限制；
> 消失的是**那个可跨格式的物体标**本身。

### 4.4 ★ 四格图：**从来没有一格同时拿到两者**

| | 绑定到词 | 跨读出方向 |
|---|---|---|
| post-norm + 欠定设置（P5–P8） | ❌ 落差 0.017 | ❌ F3 0.770 但那是物体标 |
| L7 + 欠定设置（P9） | ❌ 落差 0.018 | ✅ **0.940** |
| post-norm + 强制（P10） | ◐ 0.350 | ❌ 0.565 |
| **L7 + 强制（P10）** | ✅ **0.070** | ❌ **0.608** |
| **L1 上下文注入** | ✅ **构造上必然** | ✅ **0.905 / 0.995** |

> **⟹ 参数化路线在本项目测过的每一种配置里，最多只能拿到两者之一；
> 而上下文注入两者都有。** 这是目前对该路线最强的一条负面证据，必须写进论文。

## 5 ⚠️ 限制

1. **两臂的优化量不对等**：900 epoch 是为让 post-norm 收敛而定的（它 ep900 才到 1.00），
   而 **L7 在 ep150 就 loss 0.000** ⟹ L7 多训了约 6 倍，**可能过拟合**
   （逐用户 held-out F1 方差极大：1.00/1.00/**0.48**/1.00/1.00/1.00/0.92/…）。
   **L7 用 150–300 步的早停版未测**，那可能改变 §4.2 的泛化数字。
2. **只逼了"两词互斥"这一种形态**；三词以上、非互斥、部分重叠的含义未测。
   两词互斥时记忆只需编码**一个轴 + 一个随词翻转的符号**，比真实词汇简单得多。
3. **泛化 0.770 vs 0.992 的对比不是严格控制**：P10 训练量翻倍（24 vs 12 条）、
   任务也更难，**不能**归因为"绑定必然损害泛化"，只能说**在本设置下同时成立**。
4. 单模型、单 seed、8 用户；probe 每格式 5 正 5 负。
5. post-norm 训练 acc 0.974 而非 1.000（ISO-03 只有 0.792）——个别用户未完全收敛。
6. **base 逐用户方差极大**（F1 0.240–0.880）⟹ 单个用户的极端值**不可单独解读**。
7. **参照臂是后补的**——主脚本初版漏了，这类遗漏应在设计阶段就堵住。

## 6 复现

```bash
python p10/p10_forced_binding.py --layers post-norm,7    # 默认 900 epoch
python p10/p10_forced_binding.py --layers 7 --merge      # 只补 L7 并入已有 JSON
python p10/p10_ref_arms.py                               # ★ base / L1 参照臂（不训练，约 2 分钟）
```

⚠️ **每个用户跑完即落盘**（P9 丢过 99 分钟、P10 又整条臂丢过一次——第三次才修）。
⚠️ 单条件在 M 系列 MPS 上约 40–90 分钟。
