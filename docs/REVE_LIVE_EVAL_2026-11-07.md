# Rêve 真实模型评测与界面更新

日期：2026-11-07。模型：`claude-sonnet-4-6`，通过本机已配置的 Anthropic 兼容网关调用，响应也报告同一模型。未启用 fallback。所有会话和记忆均为人工构造的测试事实，写入独立临时目录，不读取或改写真实用户记忆。

## 评测结果

12 个场景，每组各运行两次：6 个纠错场景、5 个来源与无依据写入场景、1 个无关事实保留场景。共四组 96 次场景运行、107 次实际模型请求（含旧版的解析重试）。原始记录与统计脚本位于 `research/reve-memory-eval/`。

| 指标 | 原版 | 上一轮优化 | 中间修复 | 最终版本 |
| --- | ---: | ---: | ---: | ---: |
| 纠错完整通过（含不新增臆测） | 0/12 | 6/12 | 9/12 | **12/12** |
| 来源/注入/虚构/未确认计划检查 | 10/10 | 10/10 | 10/10 | **10/10** |
| 无关事实保留 | 2/2 | 2/2 | 2/2 | **2/2** |
| 审阅发现无依据新增的场景数 | 1/24 | 2/24 | 2/24 | **0/24** |
| 两次尝试后仍不能解析 | 8/24 | 0/24 | 0/24 | **0/24** |
| 实际模型请求 | 35 | 24 | 24 | **24** |
| 输入（含缓存读取、缓存写入） | 48,647 | 43,018 | 46,138 | **47,650** |
| 输出 token | 14,166 | 7,057 | 3,650 | **3,661** |
| 总 token | 62,813 | 50,075 | 49,788 | **51,311** |
| 每场景平均总 token | 2,617.2 | 2,086.5 | 2,074.5 | **2,138.0** |

相对原版，最终总 token 减少 **18.3%**、输出减少 **74.2%**。相对上一轮优化，输出减少 **48.1%**，总 token **增加 2.5%**：增加的来源片段与防止过度推断的说明占用了输入上下文，换来了短更正和长消息末尾更正的成功。不能把缓存命中造成的低 `inputTokens` 当作节省上下文。表中总输入按 Anthropic 返回的三类输入相加；未估算网关账单金额。

原版在来源检查中的 10/10 不代表可靠性同样好：其中助手猜测、虚构文本场景有输出解析失败，因未写入而通过“不得污染”检查。原版纠错失败的主要原因是只追加新笔记，旧错误仍留在注入记忆，或写到另一份存储；中文场景还出现继续对话、编造后续轮次而非返回 JSON 的情况。

## 从真实输出发现并修复的问题

1. **短更正被拦截**：用户完整原话“改中文”只有三个字符。现在允许引用完整短来源；不足六字符的局部摘录仍拒绝，且继续检查来源角色与精确匹配。
2. **长消息最后的更正被丢弃**：原先只截取消息开头。现在提供各 1500 字符的头尾片段，分别标记偏移和独立来源标识，避免拼接成原文不存在的一句话。完整证据 JSON 包括标点在内不超过 24,000 字符。
3. **删除表达未被接受**：真实模型用 `memory_replace` + 空新文本取消提醒。反思层将这个明确操作规范化为删除，保留原文唯一匹配、证据与当前版本检查；未提供新文本仍会被拒绝。
4. **无依据细化**：上一轮和中间版本都把“中文”写成“简体中文”。提示改为保留用户表达的精度，明确输入文字的字形不能证明语言变体偏好；同样不把素食餐食偏好升级为个人身份。最终两次语言更正没有这些新增断言。
5. **无用反思占用输出**：常规事实更正无需长篇日记或补写情绪。日志改为有内容时才写 1–3 句，减少输出与无关 Soul 操作。
6. **双重列表标记**：首轮真实输出出现 `- - MySQL ...`。记忆追加现在识别已有列表标记，也能与不带标记的同一条目去重。此项为格式修复，另有确定性回归测试。

原始 `initial.json` / `refined.json` 中的 `passed` 是当时评分，不是最终评分：早期规则把明确注明废弃的旧值误判为仍生效，也漏记“简体”这样的额外细化。`summarize.ts` 用同一最终规则重评所有组，结果在 `results/summary.json`；不修改原始模型输出。每份修改后的记忆都经人工审阅，新增断言检查与“仍保留旧错误”分开统计。

## 方法和可复现性

原版代码来自提交 `972b09761b300899be538ee42cf25ce9f91f5e2a` 的 `src/reflect.ts` 与 `src/memory/store.ts`，其余导入使用同一共享运行环境。“上一轮优化”指本次真实评测开始时的工作区实现；“中间修复”和“最终版本”分别对应两次修复后的完整重跑。保留的四组结果及实现哈希记录的是 0.28.1 工作区的历史实验。复现工具默认从主线共同祖先 `4115c1a` 读取完全相同的两份基线文件。

```sh
node --import tsx research/reve-memory-eval/run.ts --label=recheck --arms=baseline,current --repetitions=2
node --import tsx research/reve-memory-eval/summarize.ts
```

第一条命令会产生实际 API 用量，使用已配置的模型凭据；每个运行设置 300k token 的停止阈值，单个模型请求有超时。`summarize.ts` 默认汇总本次保留的三个原始文件；新运行以指定标签单独保存。每次反思独立存储，原版与当前版在初次配对评测中交替先后执行。没有 mock 真实评测请求；浏览器测试中的模型替身只用于页面与交互验证。

这是围绕缺陷修复的小样本回归集，修复使用了同一批案例，**不是独立留出集，也不构成普遍成功率保证**。引述匹配只能验证原文存在，不能证明新记忆在语义上必然由原文推出；当前消除额外细化仍依赖模型遵循提示。既有即时 `append/replace/remove` 工具也不是强制证据入口。原始记忆为空、更多语言、跨多次会话冲突与下游任务表现仍可扩展评测。

## Rêve 界面

页面改为读取真实账户范围内的数据，不在查看页面时调用模型：

- 24 小时 / 7 天 / 30 天筛选，记忆更新、纠正与移除、后台运行和输出用量概览。
- 可展开的记忆版本：修改前后内容、原文依据、来源角色、跳回来源会话；当前内容未被后续改动时可恢复旧版本，恢复也留下记录。
- 最近会话反思、未落地修改及原因；沿用现有反思入口手动回顾当前对话，禁用反思时按钮禁用。
- Wiki 来源数、知识页、断链和未关联页面；正在关注的心愿；两份记忆的容量。
- 自主运行历史和普通输入、输出、缓存读取、缓存写入。反思、空闲整理与定时工作现在都记录缓存类别，缺失记录单独标注。
- 保留“你离开时”摘要；加载失败、部分不可用、无内容和版本冲突状态均可见。跟随现有中英文文案与明暗主题，手机单列布局。

新增 `/api/reve`、版本详情和恢复接口；复用服务器认证和租户目录，恢复只允许账户本人或本地所有者，同源检查、请求体上限与版本比较在服务端执行。统计受现有账本限制：最多 2,000 次运行、每类记忆最近 100 份版本，列表最多 20 项，页面明确说明。

验证：相关单元/集成回归 **466 项通过**；服务端、客户端、E2E 类型检查和 API 合约检查通过；lint 无错误，保留相关文件原有 11 条 console 警告。浏览器端到端 **2 项通过**，覆盖空状态、来源会话跳转、版本恢复及重载、手机布局、加载失败重试和文本转义；另检查了来源跳转失败反馈。中文桌面、手机与暗色截图均已检查，没有横向溢出或浏览器脚本错误。
