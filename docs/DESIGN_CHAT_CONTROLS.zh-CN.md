# 本地 Web 聊天的授权与模型选择

## LISA 原先能修改哪些文件

从可写的源码检出目录运行时，LISA 已经能通过 `write`、`edit`、`apply_patch` 或 shell 改动自己的文件。原先本地 Web 聊天默认使用 `auto`，因此修改自身代码可能直接执行。普通沙箱的 `workspace-write` 也允许写入当前工作区内的源码。`redeploy` 可在 supervisor 启动的进程中构建并重启服务。Cloud 的聊天工具清单排除了本机文件写入、shell 和重启。

## 输入区

从本机打开 Web 工作区，输入框下方显示当前会话的审批模式、聊天模型，以及模型支持的推理强度。选择在下一次发送时生效。服务端在收到请求时固定该轮的选择。等待连接器授权的请求保存原来的选择，恢复时重新检查可用性。

| 模式 | 文件与网络 | 修改 LISA、运行主机代码、重新部署 |
| --- | --- | --- |
| 逐次询问 | 修改外部文件和联网操作逐次确认。普通本地读取可以直接进行 | 仅本次批准 |
| 智能审批（默认） | Warden 按工具、目标、沙箱范围、已授权范围和对话中的外部内容决策 | 仅本次批准 |
| 完全访问 | 启用时明确确认。常规操作在现有工具集、沙箱及 Warden 安全规则内自动执行 | 仅本次批准 |

`--approval ask` 要求每个工具调用均确认。`ask-mutating` 只提供逐次询问。`warden` 提供逐次询问与智能审批。默认配置 `auto` 允许本机用户从三档中选择。只读文件系统、Cloud 工具限制和管理员的规则继续约束执行。局域网设备和 Cloud 请求不能提交本机模式或模型覆盖。

同一标签页按会话记住模型、推理强度和常规审批偏好。完全访问只在页面内存中保存，刷新后恢复常规模式。已有客户端省略 `controls` 时，服务端也对本地聊天执行审批。CLI、后台任务及其他独立的代理入口继续使用各自的执行策略。

## 一次自修改的流程

1. LISA 读取文件、提出具体工具调用。服务端根据运行包的位置识别安装树；若从 LISA 源码检出目录启动，也识别该检出目录。独立于这两处的开发检出可以通过绝对路径 `LISA_SOURCE_ROOT` 指定。
2. Warden 检查整份补丁的目标，同时检查符号链接解析目标与实际目录项。受保护的变更进入审批收件箱。工具执行在此暂停。模型回复、附件里的文字、历史授权或切换到完全访问都不能批准该调用。
3. 本机用户在审批卡核对工具、目标和参数，选择「仅批准这一次」或「拒绝」。敏感值按现有 Warden 规则遮盖。服务端校验本机来源、请求 ID、参数摘要、有效期与单次范围，并记录决定。拒绝、超时、停止、断开连接或重启服务会终止等待。批准一次只释放对应调用；失效的请求不能重放。
4. 应用源码后，如需构建或重启，`redeploy` 会发起独立审批。生产运行的 supervisor、文件写权限和构建成功仍是部署条件。聊天授权不会更新已安装的签名 Mac 应用或发布新版本。

shell、外部编程代理、可执行扩展、带主机命令钩子的调用以及可运行项目脚本的工具，其写入目标通常无法事前枚举。它们的审批卡明确说明该调用可能改动本机及 LISA。用户授权的是显示的命令或任务。运行后，子进程能执行操作系统授予的动作。本机回环批准接口信任当前机器，同一用户运行的任意非沙箱程序也能访问它。需要抵抗已获主机执行权的程序时，须另行隔离执行身份并由独立的用户在场验证器签署批准。

## 模型路由

`GET /api/chat-controls` 向本机页面返回允许的权限、模型 ID 和推理档位。可用候选来自服务端默认模型、现有供应商配置和支持的模型清单。管理员可设置逗号分隔的 `LISA_CHAT_MODELS` 来指定候选。

```sh
LISA_CHAT_MODELS=claude-sonnet-4-6,gpt-6-astra lisa serve --web
```

候选按凭据配置筛选，具体模型的访问资格由供应商在推理时校验。手动指定的模型只走对应供应商路由；「默认」遵循实例配置，包括已有的备用模型链。选定模型时，同一会话的必要历史也会发送给对应的推理服务。模型菜单不写入实例的配置文件。

浏览器在 `POST /chat` 附带 `controls`，例如 `{"permission":"smart","model":"gpt-6-astra","effort":"xhigh"}`。服务器拒绝越过管理员上限的模式、不在清单的模型和不兼容的推理档位。模型不能通过工具参数或聊天文本提升权限。编码订阅委派、后台反思和分类使用各自已有的模型设置。

实现入口见[聊天选项](../src/web/chat-controls.ts)、[权限策略](../src/warden/chat-permissions.ts)和 [Warden 的审批及审计设计](DESIGN_WARDEN.md)。
