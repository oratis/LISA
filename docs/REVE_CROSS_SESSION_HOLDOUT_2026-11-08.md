2026-11-08，模型为 `claude-sonnet-4-6`。最初两批共 16 个新合成场景，先在提交 `36be988` 冻结题目和评分规则。独立出题 agent 未查看实现及旧输出。候选修复 `0c5bc0f` 提交后才启封第二批。每题分配独立数据目录，至少两次对话分别持久化。早先会话没有执行反思，只将末次会话传给产品的正常反思入口。

发现批中，旧实现有 6 题经过重试仍未能解析输出，记忆保留原样，这些运行计为失败。#461 能处理当次明确给出新值的更正，但用户用之前商定的代号指定码头时，模型把代号写成了正式名称；用户按上一场清单的序号选择纸张时，旧选项一直留在记忆里。

确认批逐题盲评从 **5/8 到 8/8**。例如，修复版写出了平局时按剩余贝壳最少者获胜的规则，也从早先的对应关系找到了正确的借用套件保管人。两组均未新增缺乏证据的事实。修复前有一题把志愿者的估值连同“未经测量”一起存了下来，还放错了存储；用户明令禁止保存该估值，因此这题记为违规写入。修复后只保存了允许写入的实测值。违规写入为 **1/8 到 0/8**（此处专指违反明确的禁止保存指令）。

确认批总 token 减少 **790（4.6%）**，输出 token 增加 **192（13.1%）**。四类用量来自实际服务响应，同一份缓存写入只计一次。前两批和错题复查共 42 次实际模型请求，其中发现批 22 次、错题复查 4 次、确认批 16 次，均报告同一模型。未按 token 推算金额。

## 独立评审与最终留出复测

独立评审复现了两个问题。旧版日志没有渠道标记，在同一目录工作时可能把其他发言人的渠道消息当成本人说法。另一个会话如果在当前会话进行途中才重新定义代号，新定义可能被错误地用来解释更早的决定。最终版本要求两端会话均有明确的 owner 来源，并只检索当前会话开始前的原话。它也会检查最近三段已持久化的用户发言，使最后一句简短致谢不会遮住前面的决定。

第三批 8 个新场景在提交 `6e70c0a` 冻结，用主线 `429ef5b` 与最终实现 `0e76081` 实测。每个版本用自己的原生会话写入器建立带来源的记录，另有故意构造的旧版无标记记录。初版确认批的数字保留在上表。

盲评发现，主线在两例中把已给出的规则或品名记为仍待确认，另一例把“今天签发”具体化为 2026-11-08。盲评材料含用户原话，未给虚构观测站指定时区。按原文严格计分，该日期缺乏充分依据；若假定观测站在上海时区，该日期与合成会话时间一致。采用后者，主线将是 5/8 通过、纠错 2/4、含无依据新增 2/8，修复版分数相同。另有一次保存了用户禁止记录的周五提案，单独计为违规写入。双方在旧版无标记和外部渠道各一道题中都保持两份记忆不变。总 token 减少 3,527（17.6%），其中主线有一次模型重试。

## 评分与边界

评分 agent 随机顺序查看匿名的两份存储前后内容、原始对话和冻结的标准，逐条审查新断言、被保留的旧错及明确排除的信息。之后才恢复版本标签。评分检查最终落盘内容，机器匹配和语义判读均有保留。三批均为每个版本每题一次，覆盖的是短时间内同工作区的合成对话；样本量不支持推断线上成功率，亦未测试真实用户数据。参见[评测协议](../research/reve-memory-eval/holdout/README.md)、[发现批逐项评分](../research/reve-memory-eval/holdout/discovery-audit.json)及[确认批逐项评分](../research/reve-memory-eval/holdout/confirmation-audit.json)。

检索在当前账户下，匹配同一工作目录及可核对时间的用户发言。从候选文件名中最多选择 128 个检查修改时间，最多读取 6 个会话各 32 KiB 的末尾，每次加入最多 3 段、2,200 字符，与当前证据共享 24,000 字符限额。当前发言没有唯一可核对的持久化记录时跳过补充。按词匹配和时间窗口可能漏掉遥远的对应关系。新建的个人会话和外部渠道分别记录来源。旧日志仍可打开并对当次对话反思，渠道和未标明来源的旧对话都不会被用于跨会话补充。引述证明文字存在，语义是否支持新的断言仍依赖模型。
