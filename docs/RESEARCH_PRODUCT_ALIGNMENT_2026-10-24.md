# LISA 产品对齐调研：Manus、Dot、Muse 与三端体验

日期：**2026-10-24（Asia/Shanghai）**。代码基线：main **4115c1a**，v0.28.1。

状态：公开资料研究与源码对照完成；竞品登录后操作、真实成本和成功率未实测。本文是研究结论，实施范围见 [优化方案](PLAN_PRODUCT_ALIGNMENT_2026-10-24.md)，页面规格见 [三端设计](DESIGN_CROSS_PLATFORM_ASSISTANT_v1.0.md)。完整材料在 [研究目录](research/product-alignment-2026-10/README.md)。

## 1. 结论

**建议把 LISA 从按内部模块浏览的助手，推进为围绕用户事情组织的个人工作空间。** 保留 Soft Ink、持续记忆、本地可控和多模型／多 coding agent 的特点；把主路径收敛为：交代事情 → 看见执行与阻塞 → 做必要决定 → 拿到可用成果 → 继续跟进。

三个核心参照分别补足不同部分：

| 参照 | 最值得学的机制 | LISA 应落在哪 |
| --- | --- | --- |
| Manus | 项目上下文、成果编辑、可检查的自动化 | 任务详情、资料库、试运行和成果版本 |
| Dot | 持续责任、后台委派、明确执行位置 | 主对话连接独立任务，Mac／Cloud／手机职责明确 |
| Muse | 个人语言、长期目标、低打扰、可见状态 | Today、Goals、可操作的记忆、头像融入真实工作状态 |

这些归纳是产品判断，证据分别来自 [Manus 2.0](https://manus.im/blog/introducing-manus-2-0)、[Dot 文档](https://learn.chatgpt.com/docs/dots)、[Muse 设计说明](https://introducing.muse.ai/)。对齐不等于复制 UI，也不等于一次性追齐视频、钱包、电话、硬件和所有连接器。

**LISA 最大缺口是能力的组织与交付，而非完全没有底座。** 当前已有持久 Task Engine、Warden Web 审批、Reach-out、Cloud／Mac 分离、Soft Ink 和日常任务 starters；仍缺通用任务 UI、原生可信审批、成果闭环、运行位置一致性与真实的跨端续接。[源码盘点](research/product-alignment-2026-10/lisa-baseline.md)

## 2. 范围与方法

“App”在本轮实施规划中指现有 Lisa Pocket（iPhone／iPad）；Android 先考虑移动 Web 体验，原生 Android 是单独后续决策。“Mac”包含主窗口、菜单栏、Island、后台主机与手机协作。“Web”同时覆盖登录后的应用和 meetlisa.ai 官网。

核心研究：Manus／Manus Studio、OpenAI Dot、Meta Muse。延伸研究：Cue、Claude Cowork／Dispatch、Perplexity Personal Computer。用相同维度比较：定位、首用、信息架构、输入、执行、后台工作、成果、连接器、记忆、权限、通知、运行位置、三端衔接、商业化与限制。

证据分为官方正文、官方界面示意、当前源码和推导建议。公开图示已经在浏览器查看；没有登录竞品，也未运行付费任务。来源索引包含部分抓取受限与仅检索正文的条目，已逐条标注，不能按“来源数量”理解为同等强度。[方法与边界](research/product-alignment-2026-10/README.md)、[来源登记](research/product-alignment-2026-10/sources.md)

## 5. 界面层面的判断

### 5.1 入口应表达用户要办的事

LISA 的 Rêve、Sense、Control 是内部能力名称；普通用户首先需要知道“今天有没有事需要我”“之前交代的事完成没有”。建议固定四个主入口：**今天、对话、任务、资料**。Lisa 头像承载人格、记忆和房间；连接、权限和设置保留常驻入口。项目在确有内容时出现在任务／资料的分组中。

### 5.2 头像应提供关系感，状态应提供事实

Soft Ink 表情与插画保留，但“正在思考”的表情不能替代任务已开始、失联、等待输入或已停止的证据。任务状态以服务端为准，头像仅辅助表达。手机首屏的注意力优先顺序应是待决定、正在进行、刚完成、建议用途；没有待办时再让 Lisa 的欢迎更突出。

### 5.3 对话是入口，成果需要自己的位置

旅行计划应可回看、修改和导出；简报需要来源与更新日期；草稿需要最终版本和发送状态。继续把全部产出塞在聊天 Markdown 中，会使后台工作越多、查找越困难。建议利用已有 TaskArtifact 接缝建立受控成果库，先覆盖文稿、研究报告、表格和文件，再扩展交互页面。

### 5.4 三端共享对象，交互应分别适配

- **App：** 快速交代、接收待决定、查看结果、断线恢复；iPad 可提供列表与详情双栏。
- **Mac：** 工作区、文件与本地执行、可唤起的小入口、原生审批；主窗口复用现有 Web 核心。
- **Web：** 零安装开始、跨设备查看、研究与成果处理；移动 Web 提供基本委派／结果体验。
- **官网：** 用真实可复现的场景说明价值、入口和限制，跟随实际发布状态更新。

### 5.5 将连接位置写清楚

“登录账号”“连接某台 Mac”“授权 Gmail”“在手机收到消息”是四件不同的事。当前 Cloud／Mac 历史未统一时，要保留清晰切换，不用视觉上一个头像掩盖两个数据面。统一 Home 后才可以承诺跨端同一个任务、同一份记忆。

## 6. 能力投资顺序

| 选择 | 原因 | 暂不选择的方向 |
| --- | --- | --- |
| 先把任务和结果变得可见 | 底座已存在，能直接减少找不到进度／不知道成功的摩擦 | 再新增一个独立 agent 控制台 |
| 先可信审批，再无人值守写操作 | 当前手机授权与后台接线确实缺失 | 通过放宽旧 token 权限制造功能齐全的假象 |
| 先做三条高质量完整场景 | 有助于用真实任务比较与验收 | 用连接器数量宣称“全能” |
| 先渐进改造共享 Web 壳 | Mac 已复用，避免三套界面业务分叉 | 为换外观一次性换框架 |
| 先任务来源与记忆可纠正 | LISA 已有本地记忆与审计资产 | 新增 3D／视频形象作为差异化主线 |
| 先明确 Home 与离线状态 | 直接影响信任、重试和数据去向 | 默默迁移或自动复制 Cloud／Mac 历史 |

首批三条场景：**把资料做成有来源的简报；按计划追踪变化；在手机查看并决定 Mac 上某个任务的下一步。** 第二条先使用已允许的只读能力；第三条先只读跟进，原生签名审批完成后再允许改变外部状态。

## 7. 商业化与地域

本次不制定订阅价格。Manus 价格页没有提取到完整价格卡，Dot 有资格与委派工作计量区别，Muse 公告有基本免费和订阅方向；均不足以得出同等任务的真实单位成本。[M10](https://manus.im/pricing)、[D01](https://learn.chatgpt.com/docs/dots)、[U01](https://about.fb.com/news/2026/09/introducing-muse-personal-ai-agent/)

建议 LISA 在任务上显示估算费用／已用额度、额度不足的恢复路径，以及本地自备模型和云额度的区别。不能把用户的 API 账单与 LISA Cloud 余额合成一个无解释数字，也不能暗示已有预算是账单硬上限。中文、时区、日期、导出文件名和服务可用性应进入首期设计；“有中文 UI”不等于第三方服务在所有地区可用。

## 8. 仍需实测的问题

| 问题 | 为什么重要 | 进入实施后的验证方法 |
| --- | --- | --- |
| 三个竞品同一任务真实交付率 | 演示不能验证可用性 | 合成资料、固定评分标准，每类任务重复多次，记录人工介入与失败 |
| 手机上完整审批正文的可读性 | 直接影响误操作 | 长正文、多收件人、附件及修改后重新批准的实机任务 |
| 竞品手机成果编辑深度 | 决定是否值得追齐 | 同一文档的修改、版本、导出和跨端再打开 |
| 主机休眠／网络切换后任务如何恢复 | “一直在线”常掩盖执行依赖 | 断网、睡眠、App 退出、权限撤销、错过调度分别测试 |
| 云端实际启用范围与 Pocket 功能覆盖 | 同日复核确认 1.2 美区上架，但源码、协议验证和真机 UI 是不同证据 | 参考 [Pocket 复核](REVIEW_POCKET_LIVE_2026-10-24.md)，发布前复核配置、商店版本及真机新增功能 |
| 用户更偏 Today 还是直接聊天 | 导航假设尚无用户研究 | 用同一原型完成 5 个任务，测首步选择和回找成功率 |
| 通知价值、成本、地域可达性 | 关系留存由日常使用决定 | 首批自愿用户两周观察，数据最小化采集 |

这些缺口不影响本次信息架构和工程依赖方案形成，但限制了对竞品优劣和 LISA 上线效果的断言。实施、验收与里程碑见 [PLAN_PRODUCT_ALIGNMENT_2026-10-24](PLAN_PRODUCT_ALIGNMENT_2026-10-24.md)。
