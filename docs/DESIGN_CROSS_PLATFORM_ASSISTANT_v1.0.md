# LISA 三端助手体验设计规格

**2026-10-24 设计提案。** 现状描述使用 v0.28.1 基线，后续实施进展见[方案说明](PLAN_PRODUCT_ALIGNMENT_2026-10-24.md)。 适用 Lisa Pocket（iPhone／iPad）、Mac 主窗口与常驻入口、登录后 Web 和官网。本文线框中的任务与数字均为合成示例，不表示已有功能或真实用户数据。

依据：[研究结论](RESEARCH_PRODUCT_ALIGNMENT_2026-10-24.md)、[实施方案与工作包](PLAN_PRODUCT_ALIGNMENT_2026-10-24.md)、[源码基线](research/product-alignment-2026-10/lisa-baseline.md)。当前实际视觉值仍以 [DESIGN_TOKENS](DESIGN_TOKENS.md) 和 CSS 为准；本文定义下一阶段的目标，不能据此宣称主题或导航已更新。

## 1. 体验原则

1. 每个页面回答一件事：今天看要处理的事，对话交代事情，任务看执行与阻塞，资料找输入与成果。
2. 同一个任务在三端有同一个标识和状态；执行位置、数据归属、可用动作由服务端决定。统一 Home 前，Cloud／Mac 切换仍是不同数据面。
3. Lisa 的形象提供关系感；可核对的记录提供信任。表情不能成为“运行中”“已批准”“成功”的唯一依据。
4. 默认显示结果、下一步和需要用户决定的内容；工具调用与调试记录按需展开。专业能力保留可发现入口。
5. 每个新动作必须具备等待、失败、取消、权限不足和离线状态。没有操作权限时不展示假成功或循环加载。

## 2. 统一结构与入口迁移

| 新入口 | 一级内容 | 旧入口的去向 |
| --- | --- | --- |
| 今天 Today | 待决定、进行中、刚完成、下次跟进、开始一件事 | Dashboard 的用户摘要；通知与 Reach-out 结果 |
| 对话 Chat | 主对话、最近会话、任务及成果卡 | Chat；保留会话 ID 与深链 |
| 任务 Tasks | 一次性任务、例行、关注、目标、运行历史 | Task Engine；Control／agent roster 成为相关任务的执行器详情 |
| 资料 Library | 成果、用户资料、来源；后续项目分组 | Knowledge 与导入资料；不把所有 Memory 混进文件库 |
| Lisa 个人页 | 偏好、记忆、回顾、房间 | Memory、Rêve、Room；高级检查页仍可进入 |
| 连接与设置 | 账户、执行位置、设备、应用授权、通知、模型、用量 | Settings、Sense 权限、My Mac、Mail 连接配置 |

主导航只保留四项。头像与设置入口常驻；项目有内容后出现在任务／资料的次级分组，不能在空账号上占一排空导航。邮件消息保留原有可访问入口，首期不承诺独立全功能邮箱。

旧链接通过路由别名到对应子页，保留返回来源。旧 My Mac 深链打开同一设备详情；旧 Room 链接直接打开房间。切换导航不停止后台任务，也不清空未发送草稿。

## 3. 页面布局与响应式

以下宽度是**拟议布局规则**，实施时需在 WKWebView、Safari 和 iPad 分屏验证；不是对现有 720／1180px 断点的描述。

| 可用宽度／平台 | 布局 | 交互 |
| --- | --- | --- |
| 小于 768px 的 Web、iPhone | 单列、底部四栏、顶部当前位置 | 任务详情和成果用独立页面；不把历史侧栏堆在聊天上方 |
| 768–1199px 的 Web、iPad 常规宽度 | 可折叠导航＋主内容；列表可与详情双栏 | 检查器通过抽屉打开；iPad 窄分屏退回单列 |
| 至少 1200px 的 Web／Mac | 240px 导航＋弹性主区；需要时显示 320px 检查器 | 无选中对象时不保留空右栏；主内容不足时优先收起检查器 |
| Mac 600px 最小窗口 | 精简导航按钮＋单列 | 保留 macOS 工具栏习惯，使用抽屉导航；不强制手机底栏 |

正文阅读区目标最大宽度约 760px；成果表格和文件工作区可扩展到全宽。页头固定必要状态，长列表按需虚拟化；输入框适配系统键盘与安全区。不能因底栏遮住发送、停止或审批操作。

## 4. 今天：可行动的概览

内容顺序：需要决定 → 阻塞与异常 → 正在进行 → 刚完成 → 下次计划 → 建议。每类最多显示少量条目并提供“查看全部”；排序不改变原对象状态。

每张卡包含：任务标题、当前事实、一项主要动作、运行位置和更新时间。需要决定可能是补充信息、完整审批或重新连接，必须给出不同动作名。失败卡展示可读原因与已保留成果；不把所有失败都归为“重试”。

建议来自当前可用能力、用户明确偏好或有来源的观察，可关闭、反馈“不需要”。禁止凭“可能喜欢”创建付费后台任务。无变化的例行检查进入运行历史，默认不在 Today 重复刷卡；执行失败不能混同无变化。

## 5. 对话：从意图到任务

### 5.1 输入区

- 文本始终可用；附件、录音、选中窗口／标签页由实际能力决定。缺少能力时显示原因或设置入口，不假装上传成功。
- 拖入或分享内容后先显示文件名、类型、数量与目标位置，用户可移除后发送。桌面截图和页面读取由明确动作触发，不默认读取当前屏幕。
- 录音有开始／停止与录制状态；转写可修改后发送。首期录音转写不称为实时通话。
- 快捷动作使用“整理资料”“帮我写一份草稿”“定期跟进”；只有能真正完成时才展示。发送中可继续编辑下一条，明确“停止回答”和“停止后台任务”的不同范围。

### 5.2 计划与执行

简单问题直接回答。多步骤、外部写入或较高成本任务先给紧凑计划：目标、输入、预计成果、运行位置、预算和需要决定的节点；用户可修改后开始。计划不是最终写权限，具体动作仍走 Warden。

创建任务后在对话插入稳定任务卡，后续进度更新同一张卡；详情提供完整活动。卡片至少包含任务 ID 的内部引用、标题、状态、最新进度和“打开任务”。界面不显示模型隐含推理，只显示已提交计划、实际操作与简短进度。

任务完成后的回复包括结果概要、成果入口、来源与限制，用户可以“修改这份结果”或“继续跟进”。普通聊天回复不强制创建任务，不能为每个寒暄制造工作记录。

## 6. 任务：列表、详情与例行工作

列表默认展示待处理／进行中／已完成；例行、关注、目标用类型筛选。Task 与 Run 是两层：一个例行任务有多次运行，“上次成功”不等于未来计划已停止。详情页由目标、计划、活动、成果、权限／预算、运行历史组成。

| 服务端状态 | 面向用户的状态 | 主要动作与注意点 |
| --- | --- | --- |
| draft | 草稿 | 编辑、试运行、启用；确认配置完整 |
| scheduled | 已安排 | 显示下一次实际时间及 IANA 时区；编辑、停用未来运行 |
| queued | 等待开始 | 展示排队或等待运行位置的原因；只有有证据才能说“等待 Mac” |
| running | 进行中 | 查看最近活动、补充要求、停止本次；没有可靠分母不显示虚构百分比 |
| awaiting_input | 需要你补充 | 提问与所需资料明确；回答关联同一个任务 |
| awaiting_approval | 等待决定 | 完整审批入口；权限不足时显示正确处理位置 |
| succeeded | 本次已完成 | 显示成果交付状态；例行任务另显示下一次运行 |
| failed | 本次未完成 | 原因、中间成果、可行恢复；外部结果不明先核对 |
| cancelled | 本次已停止 | 明确已发生的动作；不能把停止描述成撤销已发送内容 |
| expired | 已过期 | 解释是任务期限、等待还是授权到期；重新生成相关请求 |
| paused | 已暂停 | 展示暂停范围和原因；恢复前检查连接与权限 |

Run 的 interrupted 显示“本次执行中断”，依照服务端恢复策略更新；不能由客户端自行重新提交一次新任务。离线是连接状态，可与运行状态并存，例如“上次同步时进行中，2 分钟未更新”，不能覆盖为“已暂停”。

例行创建页包含：频率／触发来源、时区、下次运行、读取范围、命中条件、通知条件、运行位置、预算、试运行结果。试运行不隐式开启长期调度。提供“停止本次”和“停用后续运行”两个明确入口。

长期目标留待 C03：只有里程碑、子任务与完成证据接好后才显示 Goals 专门视图。现有 TaskKind.goal 可以显示为目标类型，不渲染不存在的自动推进轨迹。

## 7. 资料与成果工作区

Library 的顶层分“成果”和“资料”。同一来源可被多个任务引用，但权限与生命周期独立；删除聊天不连带删除成果，删除来源会告知哪些引用将不可打开。

成果卡包含：标题、类型、更新时间、所属任务、版本、可访问位置。先做文稿／有来源简报、表格数据和文件预览。完整编辑能力尚未支持时，提供可读预览、下载及“让 Lisa 修改”，不放一个无效编辑工具栏。

打开成果后：正文为主，来源与版本按需展开，底部或工具栏提供修改、下载、导出。下载不等于分享；外部公开分享必须另有明确对象和权限。超大、损坏、不支持类型、源文件移走、主机离线分别显示可恢复说明。

修改前建立版本快照；选中范围再发起局部修改，并显示影响范围。多端同时修改必须提示新版本或冲突，不能最后写入者静默覆盖。文件／HTML 预览的隔离要求见实施方案，不以 UI 预览绕过路径和租户校验。

## 8. 审批：完整信息与独立信任

首屏应回答：**谁在请求、准备对谁做什么、影响哪些内容、这次允许多大范围。** 页面至少包括任务、账号／应用、目标、正文／变更、附件、执行位置、风险说明和有效期。长正文可分页／展开查看完整内容，不能只给摘要或截断目标。

~~~text
审批示例（拟议能力）
任务：发送整理后的会议摘要       执行位置：我的 Mac
账号：已连接邮箱 A              收件人：完整地址列表
正文：完整待发送内容             附件：名称、大小、校验信息
授权：只允许本次这一个动作       有效期：明确时间
[查看完整内容] [拒绝] [批准本次发送]
~~~

“批准本次发送”只在可信原生签名／受支持 Web 授权成立且完整快照可读取时可用。旧配对 token 不升级为批准者。未就绪阶段显示“请在 Mac 处理”，可查看信息与返回任务；不能用隐藏按钮代替服务端鉴权。

修改目标、正文或附件会生成新快照与请求，旧批准不继承。已过期、已拒绝、已处理、权限撤销和另一台设备已处理都必须有确定状态；重复点击不重复执行。生物识别用于确认用户在场，不能替代签名、payload digest 和重放保护。

审批不以默认勾选、情感化表情或“信任我”劝用户放宽范围。日常一次批准与长期授权分开；长期授权显示范围、期限、使用记录和撤销入口。涉及跨网审批的验收前置见 B01–B03。

## 9. 各平台的特别职责

### 9.1 Lisa Pocket

iPhone 底栏为 Today／Chat／Tasks／Library，设置与 Lisa 个人页放顶部。iPad 使用系统侧栏与列表详情结构，支持分屏与键盘；共享对象语义，不强制复用手机排版。

通知深链进入指定任务／审批／成果，先验证账号和运行位置，再请求最新状态。锁屏默认“Lisa 有一件事需要你决定”，不暴露正文、收件人和文件名。由通知打开过期审批时说明已失效，不能停留在旧按钮。

离线可读已缓存且仍允许保留的摘要，标明最后同步时间。离线批准不排队；发送失败草稿留在本机并可手动重试。切换账号／位置清理相应缓存和事件连接。系统推送与前台状态刷新分别验收。

### 9.2 Lisa for Mac

主窗口继续使用 AppKit＋WKWebView，Web 内容复用导航与任务状态；文件选取、权限、可信审批保留原生边界。快捷入口支持“输入一句话／选文件／明确捕获选区”，保持可取消和当前资料预览。

菜单栏／Island 默认展示：需要决定的数量、一个最相关运行任务、打开主窗口。点击任务到同一详情，状态从任务服务读取；头像不持续播放高干扰动画。原有 agent roster 作为工作区或任务内的执行器详情保留。

关闭窗口、停止本次任务、停用例行、退出客户端、停止后台服务是不同动作。按实际安装方式解释哪个动作会让 Mac 离线；不能承诺合盖后仍执行。直接分发版与商店薄客户端按构建能力显示权限入口。

### 9.3 登录后的 Web

先登录并完成一个无需 Mac 的资料／写作任务，之后才在使用本地能力时引导连接 Mac。手机浏览器同样能发起受支持任务、查看结果与返回；桌面侧栏不占满手机首屏。

Cloud 后台任务未开启时，上述首用由已有对话能力承载；Tasks 页解释当前不可用范围，不能把普通生成伪装为持久后台任务。完整任务列表和成果链路先对支持它们的后端开放，云端随 C02 验收后启用。

账号、Cloud 余额与用户自备模型花费分别显示。模型／工具不可用、额度不足、供应商失败要保留输入和中间成果。共享计算环境与本机执行位置可解释，不能把浏览器登录态当成全部应用授权。

### 9.4 meetlisa.ai 官网

首屏用一句价值主张、一个主要开始入口、一个实际场景演示；Mac 下载和 Pocket 商店入口按设备与用户选择呈现。演示优先对应 J1–J3，只演示当前发布范围；规划中的远程审批不包装成已上线场景。

后续内容顺序：三类具体任务 → 今天／任务／成果的真实截图 → Cloud 与 Mac 的区别 → 记忆和权限如何控制 → 下载与使用条件。中文／英文保持结构和能力口径一致。

当前上架依据为 [2026-10-24 Pocket 复核](REVIEW_POCKET_LIVE_2026-10-24.md)：美区 1.2 已上架，不能扩大为全球可下载，不能把后续源码视觉等同于商店包。所有截图记录客户端版本；定价、配额和隐私文案以实际配置及适用条款为准。

## 10. 首用、连接与记忆

首用采用渐进顺序：选择可用入口 → 完成一个有价值的任务 → 按任务需要连接应用／Mac → 看到结果 → 可选择后续跟进。不要在初次聊天前一次索取辅助功能、屏幕录制、通知和所有文件权限。

连接卡显示账号、授权范围、执行位置、状态、最近验证时间和重新连接／撤销。未连接、权限不足、配置禁用、不支持、离线分别解释，相关按钮依据能力描述与服务端拒绝处理。无 Mac 是可用 Cloud 状态，不是错误。

记忆中心分“关于你”“明确偏好”“Lisa 的记忆与回顾”，每条呈现来源、时间、使用范围及可用的修正／遗忘操作。用户事实与 Soul 身份文件不能用同一个任意编辑框处理；Soul 仍遵守原子更新、版本与审计规则。纠错显示回执与生效范围。

断开应用不等于删除已记住的信息；删除记忆也不自动删除源文件或已经送出的成果。需要显示各动作实际影响的对象。Cloud／Mac 尚未统一时，记忆页顶部标注当前归属；迁移方案见 C03，禁止静默合并两个 Soul。

## 11. 视觉、文案与可访问性

延续 Soft Ink 的角色、贴纸与场景。任务页面以清晰文字和留白为主，欢迎／空状态适度使用插画，房间继续保留完整体验。新用户主题跟随系统，老用户已有 Nebula／Calm 选择不被覆盖；这是 A05 的拟议行为。

| 项目 | 新设计目标 | 与当前实现的关系 |
| --- | --- | --- |
| 正文 | Web 15–16px，行高约 1.5–1.65；iOS 使用系统正文动态字号 | 当前 Web 12–13px；逐页调整，不宣称已变更 |
| 层级 | 页面标题 24–28px；卡标题 16–18px；辅助信息 12–13px | 功能密集的高级视图另验收，不整体缩小普通页面 |
| 间距 | 沿用 4／8px 节奏，常用 12／16／24／32px | 减少同屏边框与多层嵌套卡，沿用语义 token |
| 点击范围 | 触屏至少 44×44pt／CSS px；桌面主要操作至少 36px 高 | 用真实点击区域验证，避免透明扩展区域重叠 |
| 颜色 | 继续双主题；状态同时具备文字／图标；正文对比度至少 4.5:1 | 新背景和透明叠层重新测试，不照搬旧对比度结果 |
| 动效 | 短过渡与克制状态提示；支持减少动态效果 | 无持续闪烁／脉冲要求用户注意，不用动画掩盖加载失败 |

状态文案面向用户：例如“还没有连接这台 Mac”“等待你补充资料”“上次同步于 10:32”；不直接显示内部错误码作为唯一解释。错误详情可复制用于支持，但默认不展示令牌、正文或敏感路径。

中英文标签、长文件名、多行标题、相对日期和时区需一起验证。审批中保留完整对象标识，不能为了卡片美观隐藏域名或完整目标。屏幕阅读标签包含状态和动作对象；异步更新用适当公告，不抢焦点。弹窗关闭返回触发点，所有核心路径可键盘完成。

## 12. 设计交付与验收

每个实施包交付：真实状态页面、空／等待／错误／离线变体、窄屏／大字、交互与焦点说明、能力与发布标识。页面稿必须区分演示数据与服务返回数据；后续高保真稿和截图随对应 PR 入库，不把本文线框当作已经完成的界面。

至少覆盖：375／390px 手机、768px iPad 分屏边界、600px Mac 窄窗、1280／1440px 桌面；浅暗主题；Web 200% 缩放；iOS Dynamic Type 和 VoiceOver。场景验收对应实施方案 V01–V16，重点测任务找回、审批理解、断线恢复和成果可用性。

任务状态与真实权限通过后再做美化验收。原生审批、异网到达、推送和发布状态均需独立证据；设计完成不改变任何生产开关。
