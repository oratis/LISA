# LISA 三端产品对齐方案

日期：**2026-10-24**。基线：main **4115c1a**，v0.28.1。

**状态：方案已形成，尚未实施。** 本轮交付调研、产品方案、设计规格和 docs 接入；不代表更改了产品、开启了云能力、提交了商店版本或批准了新的生产权限。旧方案已经批准的范围不因本文失效；本文新增范围按实施 PR 逐步落实。

依据：[竞品研究](RESEARCH_PRODUCT_ALIGNMENT_2026-10-24.md)、[源码基线](research/product-alignment-2026-10/lisa-baseline.md)、[三端设计规格](DESIGN_CROSS_PLATFORM_ASSISTANT_v1.0.md)。承接 [Always-on 升级方案](PLAN_ALWAYS_ON_UPGRADE_2026-09-30.md)，不另起一套 Task Engine、Warden 或 Reach-out。

## 1. 产品目标与范围

**用户能在 App、Mac、Web 任一入口交代一件事，清楚知道它在哪里做、做到哪一步、什么时候需要自己、结果在哪里。** 统一 Home 完成前，前述体验仅对同一运行位置内的任务成立，不承诺 Cloud 与 Mac 历史已经同步。

首要用户是希望处理个人资料、信息跟进和日常写作的个人，以及需要本地文件和 coding agent 协作的专业用户。默认首页服务前者；后者通过任务和工作区进入深层能力。

| 范围 | 本轮方案覆盖 |
| --- | --- |
| Lisa Pocket | iPhone、iPad 的首用、Today、聊天、任务、成果、原生审批、通知、离线恢复 |
| Lisa for Mac | 主窗口、快捷入口、菜单栏／Island、工作区、执行位置、原生审批与本地主机状态 |
| Lisa Web | 登录后的响应式应用、账号与用量、任务与成果、连接与能力解释 |
| meetlisa.ai | 官网首屏、真实场景、三端入口、模式边界与发布状态 |
| Android | 首期移动 Web；原生 App 单独立项，不在当前代码中假设已存在 |

不纳入首期：视频／游戏专业编辑器、通用购物、自主付款、独立电话号码、3D 实时角色、硬件、企业管理台、多 agent 人格商城。跨平台完成核心路径优先于功能数量。

## 2. 三条验收主线

### J1：资料变成可继续使用的成果

用户上传或选择合成资料，要求整理一份简报。Lisa 显示所用资料与运行位置，必要时给出可改计划；执行中可补充要求。完成后有概要、来源、成果预览、下载和继续修改。下一次从资料库找到同一成果及版本，不必重找聊天。

首期支持选定工作区／已上传资料，公网研究只在服务端能力允许时提供。Cloud web tools 关闭时仍可处理已有资料，不能显示已联网核验。文件解析、生成、预览三项能力分别判断。

当前 Cloud tasks 未开启时，Cloud 首用仍使用已有对话写作／资料能力，不伪造持久任务、后台进度或“关闭后会继续”的承诺。阶段 A 的持久任务与成果闭环先在已允许 Task Engine 的本地后端验收，Web、Mac、Pocket 都可连接该后端；Cloud 任务全闭环在 C02 单独验收。成果保存也必须以实际可用接口为准。

### J2：把一次工作变成稳定跟进

用户要求“每个工作日早上 9 点查看这个 RSS，只有出现某主题才提醒”。Lisa 生成草稿卡，展示时区、来源、频率、通知条件、运行位置、预算。用户可以试运行、修订并启用。无变化、失败、命中都有记录；停用未来运行与停止当前运行分开。

首期只提供现有且被允许的只读工具。连接器事件源不是现有 watcher 的别名；增加 SaaS webhook 时另做认证、事件去重和恢复。

### J3：手机接续 Mac 上的工作

Mac 发起选定目录内的资料整理任务，手机查看状态与候选变更；需要决策时手机打开完整快照。原生可信审批就绪后，用户授权具体动作，Mac 执行一次并回传结果。Mac 离线时明确等待主机，不能暗中转云或声称操作已完成。

阶段 A 仅完成可达网络中的任务查看；跨网可靠到达、签名审批和任务写入分别由阶段 B 的前置保证。没有这些前置时，明确提供“在 Mac 处理”，不展示假可用的批准按钮。

## 3. 统一信息架构

| 入口 | 内容 | 原有能力如何安放 |
| --- | --- | --- |
| 今天 Today | 需要你决定、进行中、刚完成、下一次跟进、少量可执行建议 | 摘要和通知汇入，mood 缩为关系层 |
| 对话 Chat | 主对话、历史、任务卡、附件与成果、可选规划 | 原聊天保留；关联任务可独立打开 |
| 任务 Tasks | 待处理／进行中／已完成；例行／关注／目标筛选；运行历史 | Task Engine 成为主源；coding agent 通过引用挂接 |
| 资料 Library | 成果、用户资料、来源和项目分组 | KB 保留；导入资料与生成成果分开标识 |
| Lisa 个人页 | 形象、偏好、记忆、回顾、房间 | Soul／Reve／Room 渐进展开；专业检查入口保留 |
| 连接与设置 | 运行位置、设备、账户、连接器、授权、通知、模型与用量 | Cloud／Mac 配置分离不被 UI 改造破坏 |

移动端底部四栏是 Today／Chat／Tasks／Library；Lisa 与设置在顶部个人入口。桌面左侧同样四项，项目与最近对话为次级分组；右栏只随选中的任务／成果出现。页面细节与文字线框见 [设计规格](DESIGN_CROSS_PLATFORM_ASSISTANT_v1.0.md)。

## 4. 能力模型与数据衔接

### 4.1 先复用已有接口

现有接口包括 /api/tasks、任务详情／run／cancel／runs、/api/approvals、审批详情／approve／deny、/api/warden/rules／grants／audit。事件契约已有 task_updated、task_deleted、task_run_started、task_run_finished、task_result、approval_requested、approval_resolved。[契约](../contracts/lisa-api-v1.openapi.json)

实现时以契约生成源和生成脚本为准，更新 TypeScript／Swift 共享协议；未知枚举与新增字段容错。不能将“已有 generated DTO”误认为 iOS 的请求、页面、恢复逻辑已经接好。

### 4.2 增量模型，不新建平行执行器

以下均为**拟议增量**，字段最终以 API 设计 PR 为准：

| 对象 | 复用 | 需要补充 |
| --- | --- | --- |
| Task / Run | 当前任务、kind、state、host、预算、运行记录 | origin 的稳定 conversation/message 引用；客户端可用动作；计划版本；结果验收状态 |
| WorkReference | 当前 Task ID、dispatch／observer session ID | 只做关联索引，区分可控制的任务与仅观察的会话；不复制调度逻辑 |
| TaskArtifact | 现有 text / link / file | 稳定 ID、owner、task/run、类型、版本、来源、位置与访问权限；兼容旧 value |
| AttentionItem | approval／awaiting_input／失败／连接过期事件 | 一个聚合读模型，保留原始对象 ID 与真实处理端点；不新造第二套审批状态 |
| Connection | 现有账号、设备、配置、consent | 实际账号、读／写权限、到期状态、运行位置、可撤销操作 |
| Goal | 已有 TaskKind.goal | 里程碑、子任务引用、完成证据、下一次复查；不是靠 enum 就宣称长期规划已实现 |

拟新增只读能力描述接口（名称暂定 /api/client-capabilities）：按认证用户、运行位置、客户端版本返回 available／needs_setup／disabled／unsupported／offline 及原因。它用于 UI 解释，**不授予权限**；所有操作仍走服务端现有策略。旧服务端没有该接口时保守降级，禁止默认全开。

### 4.3 成果闭环

先做文稿／研究报告、表格数据、文件预览三类，复用已有 Markdown 和 TaskArtifact；每个结果要有明确成功标准与来源。区分“运行结束”“成果已生成”“用户可打开”“已交付给指定对象”，不得一概称完成。

本地成果从经过授权的文件读取／下载接口取回；不能把任意路径当 URL。预览校验类型、大小、租户与路径边界；HTML 使用隔离预览，禁止成果脚本继承主应用权限。导出与外部分享分别授权，默认不产生公开链接。

修改采用版本快照与选定范围；旧文件可回看。引用记录 URL／源文件标识、获取日期及对应内容位置，不能依赖模型随口生成链接。先保证交付质量，再扩展 Office 深度编辑、幻灯片和交互式页面。

### 4.4 审批闭环

Web 现有完整 payload＋digest 继续复用。原生审批增加可信设备身份及签名，签名内容至少绑定 account/home、task/run、approval ID、payload digest、scope、有效期和服务端一次性 challenge；服务端验证设备、撤销状态与重放，实际执行前再核对目标和快照。

手机旧配对 token 只能保持现有权限，不能因为“同一账号”就升级成审批者。Mac 审批者与 agent 进程分离，私钥在受保护的原生存储内；生物识别不是单独的安全边界。处理 Warden 已记录的根工作目录与 loopback 自批问题后，才评估默认启用。[当前限制](DESIGN_WARDEN.md)

审批修改正文／目标后必须形成新请求；过期、撤销、已处理、主机状态变化不能静默重用旧许可。重启后旧请求失效，客户端应显示原因和重新生成入口。任务恢复沿用原 run 与副作用账本；外部调用结果未知时核对实际结果，不能盲目重试。

### 4.5 连接与 Home

第一阶段保留 Cloud／Mac 数据面并展示明确位置。第二阶段实现可达性、设备状态和授权；Home + Relay 按既有架构推进，传输加密、设备撤销、消息过期和推送租户隔离必须先验收。账号认证不自动替代本机配对授权。

统一 Home 是显式迁移：选择权威 Home → 备份与清单 → 用户选择迁移对象 → 暂停冲突写入 → 校验 → 切换 → 保留可回退快照。凭据不随普通资料导出；不能自动合并两个独立 Soul。断线不撤销授权，撤销授权也不删除历史，二者在 UI 分开解释。

## 6. 视觉与工程实施方式

1. 延续 Soft Ink；新用户跟随系统主题，保留老用户选择。字号、间距、语义状态与组件结构按设计规格渐进统一，不重新生产整套形象资产。
2. 保持 AppKit＋WKWebView 主壳，先从现有 main.js 提取状态／API 适配与任务组件，不要求一次性迁移框架。新模块只共享契约与业务状态，不把 SwiftUI 降为网页缩放版。
3. 导航切换保留旧深链别名和会话 ID；迁移期间功能开关可回退到旧壳。不能由于新列表排序而改写任务状态。
4. SSE 恢复后全量核对任务／审批快照；使用去重 ID，防止多端重复卡片与旧响应覆盖新位置。切换 Cloud／Mac 必须停止旧流、清空对应缓存并重新认证。
5. 所有新存储按 owner/home 隔离，沿用原子写、版本与迁移；访问控制测试覆盖任意 ID、路径穿越与跨租户事件。生成成果不可绕过主应用 CSP。

## 8. 衡量效果

北极星沿用“每周成功托付的任务数”。一次成功必须同时满足：运行完成、交付物／目标证据可用、用户无需重新从头描述。仅生成一条最终回复不计成功。

以下数值为**建议的首轮验收目标，非现状数据、非竞品水平**；先采集两周基线再调整。

| 指标 | 定义与建议目标 | 采集约束 |
| --- | --- | --- |
| 首次价值 | 首次进入到完成一个可用结果，中位 ≤5 分钟；同时报告需手动设置比例 | 不把等待网络／授权的用户排除分母 |
| 任务可找回 | 测试用户在 15 秒内找到指定结果 ≥90% | 固定任务脚本，不靠熟练开发者自测 |
| 核心任务完成率 | J1–J3 每条在受支持环境 ≥90%；另报人工介入 | 不把运行结束等于结果成功 |
| 审批可理解 | 能正确说出目标、影响、范围 ≥90%；错误收件人批准为 0 | 合成长正文与多附件任务 |
| 跨端状态 | 在线状态更新 p95 ≤3 秒；重连后 5 秒内恢复可见真值 | 单独报告离线／后台系统限制 |
| 前端响应 | 输入与本地状态操作 p95 ≤100ms；首屏可交互目标 ≤2 秒 | 固定设备／网络，不计模型生成速度 |
| 主动消息价值 | 有用反馈率目标 ≥70%；同时报告反馈覆盖率与停用率 | 不将没点反馈视为有用 |
| 可控性 | 未授权副作用、跨租户数据、自动重复外发均为 0 | 任何一次触发暂停相关写能力 |
| 成本 | 每成功任务估算成本、真实账单对账差异、失败消耗 | 不收集正文／文件名／地址；预算不是保证账单上限 |

事件只记录任务类型、运行位置、匿名化 ID、状态、耗时与费用区间；原始对话、附件和审批正文不进入产品分析。自托管默认保留本地统计；外发遥测需明确设置。没有样本量就不下转化提升结论。

## 9. 发布、迁移与回退

| 风险 | 发布门槛 | 回退 |
| --- | --- | --- |
| 新导航影响老用户 | 旧路由映射、快捷键、最近会话可恢复；专业模式入口保留 | 切回旧壳，任务数据不变 |
| UI 展示不等于服务端支持 | 能力接口＋服务端拒绝路径；测试 default／opt-in／cloud 三种配置 | 关闭对应入口；已有结果仍可读 |
| 原生审批误授予能力 | B01 威胁模型、签名与撤销测试通过 | 禁止新的原生批准；未处理请求失效，回到受支持的人工处理 |
| 长任务／外发重复 | checkpoint、lease、idempotency、未知结果核对 | 暂停写任务，保留账本与审计，人工对账 |
| Cloud 扩容导致重复调度 | 共享状态和审批路由验证，或明确单实例约束 | 关闭新任务启用，排空运行，不删除用户任务 |
| Home 迁移丢失／串数据 | 清单校验、范围选择、快照与恢复演练 | 回到旧 Home；禁止两边同时写 |
| 官网／App 文案提前承诺 | 每个能力有版本、渠道和验证记录 | 降回当前可用文案，保留提案在 docs |

灰度顺序：本地开发合成数据 → 自愿内部测试 → 少量真实用户 → 分端发布。用户是否获得功能取决于客户端、后端和权限共同满足；发布说明分别记录 source merged、binary shipped、cloud enabled、store available。
