# 关键不变量

以下规则适用于后续修改与审查。

## 权限与工具

1. Cloud 用户不能因为 Web 服务复用了 CLI 组合根，就获得宿主机文件、Shell、任意工作目录、运营方插件或 MCP 的能力。
2. 能力限制必须在服务端执行；UI 隐藏、Edition 标记和客户端判断不能作为安全边界。
3. 自动触发、用户触发、管理员触发和远程代理触发必须携带明确的 capability profile。
4. 任何 URL 抓取或邮件服务器连接都要防 SSRF：解析 DNS、阻断私有/保留地址、处理重定向和 DNS rebinding，并有出站策略。
5. 高权限工具调用必须有可查询审计记录；日志不能泄露 Token、邮件验证码、完整对话或支付凭据。

## 身份与租户

1. 所有租户数据访问都必须由当前认证 UID 决定，不能信任客户端提供的路径或 UID。
2. 进程内状态必须显式按租户分区，并有 TTL/LRU 或容量上限。
3. 最近活动、Advisor、Island、历史记录、计划和配置不能跨租户共享。
4. 代理头只能在可信反向代理边界后使用；不能直接信任任意 `Host`、`X-Forwarded-For` 或 `X-Forwarded-Proto`。
5. 邮箱验证和密码重置链接只能由服务端配置的规范公网 Origin 生成。

## 计费与交易

1. “交易去重成功”和“余额入账成功”必须处于同一原子事务，或由可恢复的状态机与对账器保证最终一致。
2. 账户、余额、交易索引损坏或读取失败时必须 fail closed；只有明确的“文件不存在/首次创建”可以初始化为空。
3. 全局花费上限、用户额度和并发租约不能因缓存缺失或存储异常而 fail open。
4. 每一条模型推理路径都必须经过统一的认证、额度检查、成本预留、结算与审计，包括聊天、反思、出生流程、语音润色、自治和后台任务。
5. 支付回调与 IAP 必须支持幂等重试、对账和人工补偿。

## Context、Soul 与自治

1. Web 长会话必须有 Token 窗口、压缩或会话滚动，不能无限加载全部消息。
2. Reflection 必须以会话/消息水位和幂等键为基础；同一输入不能重复生成 Soul 操作。
3. Soul 写入保持路径限制、原子写、锁、审计和 Git 溯源。
4. 自治任务必须有预算、租约、超时、取消、重试上限和公平调度。
5. 外部知识与网页内容始终是不可信数据，不能升级为系统指令。

## HTTP 与协议

1. 所有请求体都有显式上限、超时和 Content-Type 校验，附件与音频使用更严格的独立限制。
2. 路由的认证、权限、计费和能力需求应由集中元数据或中间件表达。
3. TypeScript 服务端与 Swift 客户端共享一个可版本化的协议源，并保留客户端容错解码。
4. 破坏性协议变更必须有迁移窗口或版本路由。

## 变更完成标准

- 运行相关单元与集成测试；
- Cloud 权限变更包含“拒绝路径”测试；
- 计费变更包含失败注入、重试和对账测试；
- 持久化变更包含损坏数据和迁移测试；
- 原生 API 变更验证 macOS/iOS 编译；
- 更新 `.codex` 中已经失效的事实。
